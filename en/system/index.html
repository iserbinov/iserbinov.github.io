frame/principlesite system

Principle

Every value gets a role, and a component takes the role, not the value. That is why theme, accent, radius, and density change in one place. Colors, radii, and spacing are tokens; font sizes and small adjustments are written directly in the rules

A value gets a role.
A role builds a component

Terms

Words used further down. If a term is unclear, come back here

Token
A named value: a color, size, radius, or typeface. Defined once, in base.css
Role
What a token is for, such as “text” or “accent fill”. A component references the role, not a specific color
Sheet
The white card that holds the page content (.sheet). Its padding and radius depend on the window width
Frame
The frame/name label above a sheet (.frame). Shown together with specs
Specs
An overlay on top of the page with sizes and tokens (.ov). Turned on with the specs toggle
Ramp
A row of shades of one color, from light to dark; only lightness changes
Pill
A fully rounded shape, like the link button (--r-pill)
State
How an element looks at a given moment: default, hover (pointer over), active (pressed), focus (keyboard focus)
frame/colorsite system

Color

There is one accent, and it plays two roles: text and fill. Neutrals create depth, and the light and dark themes use the same token names

Color logic

Surfaces: three layers

canvas is the page background. bg is the sheet. surface is everything that sits on the sheet: cards, tags, and inputs

One accent, two roles

accent is for text, focus, and the “now” label. accent-fill is for buttons, spec lines, and the “now” bar on the timeline. One hue; lightness is tuned per theme

Text: two levels

fg for primary text, muted for secondary. Both pass AA on bg and on surface

Dark theme

Neutrals invert. Accent text gets lighter and the accent fill gets darker, so the fill never glares

Lines

line is for dividers. edge and shadow are the sheet’s outline and shadow

Changing the accent

The chosen color sets hue and chroma. Text lightness is adjusted automatically until contrast reaches 4.6:1 on bg and surface

Ramps and derived colors

Neutrals: bg, canvas, surface, line, muted, fg. Accent: oklch, hue 221°, chroma 0.085. Only lightness L changes

Typesetting rules

The site’s typography is checked on every page, this one included

No hanging short words

A non-breaking space follows one- and two-letter words such as a, an, in, on, of, to, at, by, or, and I, so they never end a line. Chains of such spaces stay within 24 characters, otherwise the line breaks badly. Checked at widths from 320 to 1920 px

Numbers stay with their units

A non-breaking space also sits between a number and its unit: 4.3 million, 48 px. Ranges use an en dash: 2014–17

No period at the end of a paragraph

This applies to paragraphs, list items, and captions. Periods between sentences inside the text stay

Curly quotes, no em dashes in running text

Use a colon, a comma, or a full stop instead of an em dash. The exceptions are the title and description tags

Very long words wrap

If a word does not fit the column, such as an email address at a larger font size, it breaks between letters (overflow-wrap: anywhere) instead of running off the screen

Header and menu

Shared by every page. Navigation keeps Work, Tokens, About, and Contact; on a phone everything except the logo moves into the menu

The header is sticky

Pinned to the top with an s2 offset on layer 20. Its height is the --bar-h token: 48 px on desktop, 60 px up to 820 px. Elements below rely on it: the documentation index sticks at calc(s2 + --bar-h), and anchor jumps get scroll-padding-top so a heading never hides under the header

Up to 820 px only the logo and Menu remain

The logo doubles as the site address. The Menu button opens a panel with navigation, the theme toggle, and the language switch. The tap target is at least 44 px. The panel closes on Esc, on a tap outside, after choosing a link, and when the window grows past 820 px

Tokens opens as a list

The item is a native details: Site tokens leads to the card on the home page, Documentation to this page. The current page is marked aria-current="page". The list closes on Esc, on a click outside, and when another one opens

The header works without scripts

The menu and the Tokens list are enhanced by a script. If it does not load, navigation stays as plain links

frame/a11ysite system

Accessibility

The site can be read and operated without a mouse, without telling colors apart, and without motion. Every rule can be checked in the code and by hand

Structure and language

The site meets level AA

The target standard is WCAG 2.2, level AA. The criteria are checked by hand and with scripts on every page; there has been no independent audit yet

Headings are in order

Each page has one h1 and no skipped levels. The language is set with lang="en", and the “RU” link is marked lang="ru"

The first link skips the header

The “Skip to content” link appears on focus and leads to main. Keyboard users do not have to tab through the whole header

Meaningful images need alt

The text says what matters in the image. Decorative images get an empty alt

Panel fields are named

Fields and groups in the Site tokens panel are tied to their labels through aria-label and aria-labelledby. Preset colors are named in words: “blue”, “green”

Screen readers: tags and markup

A screen reader reads structure from tags, so the site is built from semantic elements rather than anonymous divs

Page landmarks

header, nav, main, and footer on every page. The menu is labeled: aria-label="Main"

Sections and headings

Every section is a section with aria-labelledby, and headings h1–h3 have no gaps. A screen reader lists them as a heading outline

Lists and captions

Enumerations use ul, ol, and dl. Illustrations sit in a figure with a figcaption, so the caption is read together with the image

Tables and lists in case studies

Where the layout does not use native tags, roles are set explicitly: table, row, columnheader, cell, list, and listitem

States are announced

An expandable row is built on details, the specs toggle carries aria-pressed, the current language is marked aria-current, and an unavailable one aria-disabled

Decoration stays silent

Pluses, arrows, and the specs layer are hidden with aria-hidden="true", so a screen reader skips them instead of cluttering the output

Keyboard and focus

Everything works from the keyboard

Tab order matches the visual order. Expandable rows open with Enter and Space

Focus is always visible

A 2 px outline in accent with a 3 px offset (4 px on color swatches). It appears during Tab navigation and stays out of the way of the mouse: :focus-visible handles that

Enlarging an illustration without a mouse

An image in a case study opens in a dialog with Enter or Space. Close it with Esc, a tap, or the Close button; focus returns to the image

The theme toggle says what it does

The toggle shows the current mode in words: “auto”, “light”, or “dark”

Contrast and color

Text meets AA at least

WCAG level AA: 4.5:1 for regular text and 3:1 for large text, in both themes. All pairs are measured in the Color section

A custom accent stays readable

When you pick a color in the tokens panel, text lightness is adjusted to 4.6:1 on bg and surface

The accent fill carries no text

accent-fill on bg is 2.19:1 in the light theme, so text on the fill uses on-accent, and the fill is never the only carrier of meaning

Meaning never rests on color alone

The selected option is underlined or ringed, the “now” label has text, and an open row turns its plus into a cross

System settings

The site reads browser and operating system settings and adapts to them. On desktop and on phones these are the same CSS conditions

Theme

prefers-color-scheme sets the default theme. The toggle switches it to light or dark and remembers the choice. All three modes work together

Motion

With prefers-reduced-motion: reduce, transitions and smooth scrolling are switched off. Other animations exist only where they help explain what happened

Contrast

With prefers-contrast: more, secondary text and lines take the primary text color, and borders become easier to see

Forced colors

In forced-colors mode (Windows high contrast themes), blocks and the dropdown menu get a visible border, and color swatches and the menu icon stay visible

Font size

All text sizes are set in rem. The browser font size setting and Dynamic Type on iOS scale all text at once. On Android the site is ready for the system font scale through the text-scale tag, but Chrome does not apply it everywhere yet. Platform details are in the table below

Page zoom

Ctrl and + on desktop, pinch on a phone. The viewport tag does not block zooming

Target size

Targets are at least 24 px

Links in the header, footer, and contacts are at least 24 px tall (WCAG 2.5.8)

44 px on touch devices

The pointer: coarse condition stretches toggles, color swatches, and the “default” button in the tokens panel to 44 px

Zoom: what happens when you enlarge

You can enlarge the site in two ways: zoom the page or change the text size. Platforms support them differently

Nothing breaks at 400%

A 320 px width equals 400% zoom on a 1280 px screen (WCAG 1.4.10). No page of the site scrolls horizontally

Text stays readable up to 200%

With the browser font size at 200%, text is not clipped or overlapped and there is no horizontal scrolling (WCAG 1.4.4)

The site scales smoothly, not in jumps

Large headings change size with the window width through clamp(). Body and small text keep their size while the grid reflows

Content does not stretch

The page width is capped at 1190 px. On large screens only the empty side margins grow, so lines stay at a readable length

The main breakpoint is 820 px

Here the intro and contacts collapse to one column, list rows simplify, and the timeline turns vertical. Extra breakpoints: 640 px for case studies and 480 px for narrow phones
